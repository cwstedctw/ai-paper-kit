# 研究論文範本（ai-paper-kit）：老師的使用說明

**一句話：你不用打指令，也不用學 LaTeX。你跟 AI 說話，AI 去改檔、跑程式；你看 PDF、做決定。**

這個資料夾是一個「AI 研究小隊」加上一條論文流程：

**找文獻 → Zotero 管書目 → 分析資料 → gnuplot 畫圖 → LaTeX 寫稿 → 編出 PDF（也能出 Word）**

**範例用的是一篇已發表的居服員失智照護訓練研究（2021 年，*BMC Geriatrics*，開放取用、CC BY 4.0；完整書目是 `source/refs/refs.bib` 裡的 Su2021）**（140 人，兩組，DKAS、ADQ、SCIDS 三個時間點）。原始資料沒有公開，所以範本裡放的是**依論文表格重建的練習資料**：平均與標準差四捨五入後跟論文一樣，表 1、表 2 的 p 值相同、效果量最多差 0.01，每個人的分數是假的，不能拿來下結論。範例論文（9 頁）示範怎麼用程式把論文的表 1、表 2、表 4 重算一次，並逐一跟論文印的數字對照。先照下面跑一次範例、做一次練習，再換成自己的研究。

---

## 一、你要做的只有三種事

| 你做的事 | 例子 |
|---|---|
| **跟 AI 說話** | 在 Codex 或 Claude 的 Code 貼下面第六節的句子 |
| **放東西、管文獻** | 把去識別化的資料放進 `source/data/`；在 Zotero 加文獻 |
| **看成品、做決定** | 打開 `output/main.pdf`；決定統計方法、文獻、結論說到多強 |

AI 每次要跑程式或改檔，會先問你可不可以。看得懂就同意；看不懂就問它「這一步在做什麼」。

## 二、資料夾怎麼分：原料放 source，成品在 output

```
source/            原料：要改論文，就改這裡
  data/            研究資料（CSV）              ← 你放進來
  refs/            書目 refs.bib                 ← Zotero 自動匯出
  scripts/         分析程式 analyze.py          ← AI 改
  gnuplot/         畫圖腳本，一張圖一個 .gp      ← AI 改
  paper/           論文本文 main.tex             ← AI 寫
          │
          │  uv run build.py（跟 AI 說「跑一次 build」）
          ▼
output/            成品：每次 build 重做，不要手改
  numbers.tex      內文數字，一個數字一個代號
  tables/          表：.tex 放進 PDF，.csv 用 Excel 打開核對
  figdata/         畫圖用的資料表（CSV）
  figures/         gnuplot 畫好的圖
  main.pdf         論文 ← 你看這個
```

**記住一條規則就好：要改結果，改 `source/`；`output/` 不用顧，跟 AI 說「再跑一次 build」就會重新長出來。**

其他檔案：

| 檔案 | 做什麼 | 誰會用 |
|---|---|---|
| `README.md`（這份） | 給你看的說明 | 你 |
| `build.py` | 一次跑完：分析 → 畫圖 → 檢查文獻 → 編 PDF | AI 執行（你說「跑一次 build」） |
| `AGENTS.md`、`WORKFLOW.md` | 給 AI 看的規則和流程說明書 | AI 開工先讀；你不用背 |
| `tools/make_practice_data.py` | 重建練習資料 | AI 執行，只有練習時 |
| `tools/zotero_export.py` | 從 Zotero 匯出書目（不裝外掛的接法） | AI 執行，只有用 Zotero 接法 C 時 |
| `material/` | 你的材料：計畫書、投稿須知 | 你放；AI 只讀 |
| `workspace/` | AI 的紙條、變更報告、工作紀錄 | AI 寫；想知道 AI 做了什麼時打開看 |
| `.github/workflows/` | 推上 GitHub 後，雲端自動編一份 PDF | GitHub 自動跑 |

## 三、第一次：裝工具（只要裝一次）

**TeX Live 是什麼？** 要把 LaTeX 編成 PDF，電腦裡要有一套「TeX 發行版」。最完整的一套叫 **TeX Live**；Mac 版的 TeX Live 叫 **MacTeX**；Windows 另有一套 **MiKTeX**，第一次裝比較小，缺什麼再自動補。

| | Windows | Mac |
|---|---|---|
| TeX | **MiKTeX**（打開「缺套件時自動安裝」） | **MacTeX**（約 6.4 GB，macOS 11 以上）；硬碟不夠改 BasicTeX（約 134 MB） |
| 畫圖 | gnuplot | gnuplot（Homebrew） |
| 統計 | **uv**：它會自己裝好 Python 和 numpy、pandas、scipy 等套件（放在範本資料夾的 `.venv/`，不動電腦原本的 Python） | 同左（Homebrew） |
| 轉 Word | pandoc（需要時才裝） | pandoc（Homebrew） |

在 AI 助手貼（Windows 版）：

> 請幫我裝寫論文要用的工具。每裝一個之前，先告訴我要裝什麼、從哪裡裝，我同意再裝；要我輸入電腦密碼時先停下來，我自己輸入。
> 1. TeX：用 winget 裝 MiKTeX（winget install -e --id MiKTeX.MiKTeX），裝好後把「缺套件時自動安裝」設成「是」（不要選每次問我），你在背景跑的時候才不會卡住。
> 2. gnuplot：用 winget 裝（winget install -e --id gnuplot.gnuplot）。裝好後打 gnuplot --version；如果找不到、或沒有印出版本就結束（winget 建的捷徑可能缺檔），請找出 gnuplot.exe 所在的 bin 資料夾，先告訴我你打算把它加進「使用者」的 PATH、會影響什麼，我同意再加；加完請我把 Codex／Claude 關掉重開，再打一次 gnuplot --version。
> 3. uv：用 winget 裝（winget install -e --id astral-sh.uv）。裝好後請我把 Codex／Claude 關掉重開，再到範本資料夾執行 uv sync（第一次會下載 Python 和套件，要幾分鐘）。
> 4. pandoc：winget install -e --id JohnMacFarlane.Pandoc。
> 全部裝完，請一一執行 pdflatex --version、gnuplot --version、uv run python --version、pandoc --version，把版本號列給我看。

Mac 版：

> 請幫我裝寫論文要用的工具。每裝一個之前，先告訴我要裝什麼、從哪裡裝，我同意再裝；要我輸入電腦密碼時先停下來，我自己輸入。
> 1. TeX：裝 MacTeX（brew install --cask mactex，或到 tug.org/mactex 下載，約 6.4 GB）。我的硬碟空間不夠的話，先問我要不要改裝 BasicTeX。
> 2. 用 Homebrew 裝 gnuplot、pandoc 和 uv（brew install gnuplot pandoc uv）；沒有 Homebrew 的話先告訴我。如果 brew 開始從原始碼編（訊息出現 Building from source、或跑超過 10 分鐘），先停下來告訴我，改用：pandoc 到 pandoc.org 下載官方安裝檔；gnuplot 用 micromamba 從 conda-forge 裝（只裝在使用者資料夾，不動系統）。
> 3. 到範本資料夾執行 uv sync（第一次會下載 Python 和套件，要幾分鐘）。
> 全部裝完，請一一執行 pdflatex --version、gnuplot --version、uv run python --version、pandoc --version，把版本號列給我看。

**完成判準**：AI 列出四個版本號，沒有「找不到」。MacTeX 很大，建議前一天晚上裝。

**Intel 晶片的 Mac 要注意**：新版 macOS 在 Intel 晶片上，Homebrew 常沒有現成編好的 gnuplot、pandoc，會改成從原始碼編，要好幾個小時（2026-10-22 在 Intel Mac、macOS 26 實測）。上面那句已經請 AI 遇到就停下來、改用官方安裝檔和 conda-forge，那次這樣裝不到一分鐘。Apple 晶片（M1 以後）的 Mac 通常有現成編好的版本（這點還沒實測）。

不想在自己電腦裝 TeX：推上 GitHub，雲端會自動編出 PDF，只是每改一次都要推上去才看得到。**這條路只限練習資料，或資料符合第八節四個條件**：推上去，資料就會在 GitHub 的雲端機器上被讀取。

## 四、練習：數字和圖從哪裡來（約 30 分鐘）

用範例走一次，看懂「數字由程式寫、圖由 gnuplot 畫」是怎麼回事。每一步：**你自己做**、**跟 AI 說**（直接複製）、**你會看到**。練習改的東西，最後一步會還原。

開始前（回家自己做也照這張）：
1. 範本資料夾已經在電腦裡（`ai-paper-kit`；範本從哪裡拿，當天講師會說）。
2. 工具裝好了：照第三節，AI 列出四個版本號才算。
3. 打開「看得到你電腦資料夾」的那一面 AI：ChatGPT 桌面版裡的 Codex，或 Claude 桌面版裡的 Code（網頁上的一般對話看不到你電腦裡的資料夾）。權限設成「要求核准」（Claude 的 Code 選 Manual）。
4. 範本是用 ZIP 下載解壓縮的：報到之前先跟 AI 說「請先檢查這台電腦有沒有 git；有的話幫這個資料夾存一版（commit），存好告訴我」，存好才報到。用 git 下載（clone）的不用。收尾的還原要靠這一版。

**AI 問你「可不可以」的時候**：權限是「要求核准」，AI 每次要跑程式或改檔都會先跳出確認（常是英文）。跑 build、改 analyze.py、改 .gp、改 main.tex：練習本來就要做，按同意。要刪檔、裝東西、動 `source/data/`、上網：先別按，問它「這一步在做什麼」。

**報到**
- 你自己做：在 Codex 或 Claude 的 Code 打開範本資料夾（`ai-paper-kit`）。
- 跟 AI 說：「請先讀 AGENTS.md 和 WORKFLOW.md，再跟我報到。今天是練習。開始前先確認 source/ 有沒有還沒存版的修改或新增檔；有的話先列給我、停下來。」
- 你會看到：第一行是「領隊 ·」加上資料夾路徑；它會說 source/ 有沒有還沒存版的檔。它列出檔案、停下來的話，先別讓它刪或還原，那些可能是你以前的東西。說了「今天是練習」，AI 就不會一直寫紙條和報告，練習期間也不存版，收尾才還原得乾淨。

**練習 1　看原料**
- 你自己做：用 Excel 打開 `source/data/study_data.csv`。一列是一個人，共 140 人（Excel 顯示到第 141 列，因為第一列是欄名），`dkas_t0`、`dkas_t1`、`dkas_t2` 是三個時間點的知識分數（t0＝前測、t1＝第 12 週、t2＝第 24 週）。再打開 `source/data/published_values.csv`：這是從原論文抄下來的數字。**看完關掉時，Excel 問要不要儲存，一律按「不要儲存」**：Excel 存檔可能改掉格式，程式就讀不懂了。
- 你會看到：資料就是一張表。程式只讀它，不會改它。

**練習 2　跑一次 build，看成品長出來**
- 跟 AI 說：「請跑一次 build（執行 uv run build.py），告訴我最後一行，再告訴我 output 資料夾裡多了哪些檔。」
- 你會看到：最後一行 `BUILD OK pages=9 undefined_cites=0 undefined_refs=0 refs=7 refs_without_doi=0 bib_warnings=0`。用 Excel 打開 `output/tables/table2.csv`：欄名有 published 的是論文印的數字，有 reproduced 的是程式重算的，兩欄一對並排；再打開 `output/main.pdf`。
- 這一行怎麼看：pages＝頁數；undefined_cites＝找不到的引用（要是 0）；undefined_refs＝找不到的圖表編號（要是 0）；refs＝文獻篇數；refs_without_doi＝你標了「沒有 DOI」的篇數；bib_warnings＝書目缺欄位的警告（要是 0）。

**練習 3　追一個數字**
- 跟 AI 說：「論文 3.2 節的 37.04 是從哪裡來的？請告訴我：資料檔的哪一欄、analyze.py 的哪一行算的、numbers.tex 裡的代號叫什麼、main.tex 哪一句用到它。」
- 你會看到：`study_data.csv` 的 `dkas_t1` 欄 → `analyze.py` 算介入組平均 → `output/numbers.tex` 寫成代號 `\DKASIntTOneMean` → `main.tex` 那句寫的是代號，不是數字 → PDF 排版時換成 37.04。**論文裡沒有一個結果數字是手打的。**（代號是程式把量表、組別、時間拼起來的，例如 DKAS＋Int＋TOne＋Mean，所以在 analyze.py 裡直接搜整個代號會搜不到。）

**練習 4　排除一個人，看全部一起變**
- 跟 AI 說：「練習：假設事後發現練習資料裡的 I048 不符合收案條件，請在 analyze.py 上面的 EXCLUDE_IDS 加上 "I048"，跑一次 build，告訴我表 2 哪些數字變了、論文哪幾句的數字跟著變。」（I048 是練習資料的虛構代號。這句貼給 AI 就好，不用自己打開 analyze.py。）
- 你會看到：總人數 140 → 139（介入組 70 → 69），37.04 變 37.41，效果量 d 從 0.92 變 1.01；表 1、表 2、表 3、圖、摘要和內文的數字一起更新，你不用改任何一句。重算的數字也開始跟論文對不上，Methods 會多一句要你補排除理由。**但句子的解讀不會自己改**：數字變了，用到它的句子要你重讀一次。
- 要記得：I048 剛好是介入組分數偏低的人，排除後效果看起來變大。**排除誰，要在看結果之前、照事先定好的理由決定**，不能看了結果再挑。
- 改回來：「請把 EXCLUDE_IDS 改回空的，再跑一次 build。」

**練習 5　圖從哪裡來**
- 你自己做：用 Excel 打開 `output/figdata/fig1_dkas.csv`：三列（前測、第 12 週、第 24 週），兩組的平均和標準差。圖 1 的 DKAS 小圖，就是 gnuplot 把這張小表畫出來。再打開 `source/gnuplot/fig1_outcomes.gp`：這是文字檔，按右鍵選「開啟檔案」→「記事本」（不要雙擊、不要用 Excel），每一行旁邊都有中文註解。看完關掉，問要不要儲存都按「不要儲存」。
- 跟 AI 說：「請把圖 1 改成長條圖，像原論文的 Fig. 2 那樣：兩組並排、誤差線是標準差。只改 gnuplot 腳本，跑一次 build，告訴我改了哪幾行。」
- 你會看到：PDF 的圖 1 變成長條圖，數字一個都沒變；AI 會告訴你 `source/` 裡只改了畫圖腳本（那支 `.gp`），`workspace/log.md` 會多一行紀錄，這是正常的。長條從 0 畫起，兩組的差距看起來會比折線圖小，數字其實一樣。**同一份資料，換一支腳本就換一種畫法。**

**練習 6　加一個新表**
- 跟 AI 說：「請在分析程式加算兩組從前測到第 12 週的平均改變量（和標準差），做成新的表 4 放進論文的 Results，跑一次 build。」
- 你會看到：`output/tables/` 多了 table4.tex 和 table4.csv，PDF 多了表 4（範例論文原本有表 1 到表 3，這是第四張；不是原論文裡的表 4）。AI 會提醒：改變量的標準差受重建資料時假設的相關（0.5）影響，不能當成原研究的結果。

**收尾**
- 跟 AI 說：「請列出練習改過和新增的 source 檔。我確認之後，改過的還原成練習前的樣子（git restore），新增的移到 workspace/練習留底/，其他檔都不要動，再跑一次 build。」
- AI 列完清單會等你：確認沒問題，回「確認，請還原。」
- 你會看到：最後一行跟練習 2 一樣，PDF 回到練習前。練習新增的檔收在 `workspace/練習留底/`，`workspace/log.md` 的紀錄也留著，都不影響論文。

### 看一位老師實際走一遍（2026-10-22 實跑紀錄）

我們用「不會寫程式、只用過 LINE 和 Word」的老師視角，把上面的句子**一字不改**貼給 AI，從頭做到尾。下面是 AI **真正回的話**（摘錄；資料夾路徑用「…」代替），以及每一步「這是什麼意思」。環境：Windows、Codex 桌面版內附的 Codex，同一段對話做到底（報到那句後來加了「先確認 source/」，那一步另外實跑了一次）。9 次回覆 AI 一共花了大約 7 分半鐘。為了自動錄下過程，實跑時 AI 用的是「不問、直接做」的設定，所以紀錄裡看不到「可不可以」的確認；你設成「要求核准」會多跳出這些確認。這是當次的紀錄，AI 下次的說法、行號可能不一樣，照每一步「你要檢查」核對就好。加上你看 PDF、開 Excel，30 分鐘做得完。（上一版的句子也用 Claude 做過一次，每一步一樣 `BUILD OK`。）

**報到**（AI 花 18 秒）
- 老師貼：「請先讀 AGENTS.md 和 WORKFLOW.md，再跟我報到。今天是練習。開始前先確認 source/ 有沒有還沒存版的修改或新增檔；有的話先列給我、停下來。」
- AI 回：「領隊 · …\ai-paper-kit　已讀完 AGENTS.md、WORKFLOW.md、領隊規則及 team.md。source/ 沒有尚未存版的修改或新增檔。未設定 Git 遠端，無須 pull；目前未修改任何檔案。今天採單人練習模式：不寫紙條、不寫變更報告、不 commit。已準備好。」
- 如果資料夾裡有你以前改過、還沒存版的檔（我們故意弄了一份測試），AI 回：「source/ 有尚未存版的檔案：已修改 source/paper/main.tex；新增、尚未追蹤 source/data/我的筆記.csv。依你的指示停在這裡，未改檔、未 pull、未 build。」
- 這是什麼意思：先看第一行的路徑是不是你打開的範本資料夾，再看它有沒有把練習規則講出來：這一行是報到的格式，內容還是要對。「commit」＝存一版；練習時不存，收尾才退得回去。
- 如果它說「沒有遠端，不用 git pull」：代表這個資料夾還沒接上 GitHub，練習時不影響。

**練習 2　跑一次 build**（33 秒）
- AI 回：「build 成功，最後一行是：`BUILD OK pages=9 undefined_cites=0 undefined_refs=0 refs=7 refs_without_doi=0 bib_warnings=0`。output/ 新增 28 個檔案（main.pdf 9 頁、numbers.tex、figdata/、figures/、tables/、latex-log/）……已在 workspace/log.md 記錄這次練習，沒有 commit。build 另提醒：論文中的 AI 使用聲明仍是範例文字。」
- 這是什麼意思：「build」＝一次做完分析、畫圖、檢查文獻、編 PDF。最後一行是 BUILD OK 就成功；三個「要是 0」的都是 0。`latex-log/` 是排版過程的紀錄，出錯時才要看。最後那個提醒是範本故意留的：範例的 AI 使用聲明寫的是範例作者做過的事，你寫自己的論文時要改成你自己做過的事。

**練習 3　追一個數字**（43 秒）

## 五、研究模擬：只給資料和文獻，AI 一步一步寫完

第四節是改一篇**已經寫好**的論文。這一節反過來：研究內容只靠三樣原料（另外 AI 也會看範本裡的規則、工具和收起來的範例程式）：練習資料（`source/data/`）、13 篇文獻的書目（`material/模擬/refs.bib`）和一份研究構想（`material/模擬/研究構想.md`）。你一句一句說，AI 從開一篇新論文做到交稿前檢查，最後把原本的範例放回去。

**做法**
- 開新論文：第 0 步請 AI 執行 `uv run tools/new_paper.py --keep-data --refs material/模擬/refs.bib --name 範例論文重算`。現在的範例收進 `examples/範例論文重算/`（examples＝收起來的舊論文，隨時能打開參考；資料檔不會複製進去，一律留在 `source/data/`，免得多一個地方把資料推上 GitHub），`source/` 換成新論文的骨架：練習資料留著、書目換成模擬用的 13 篇、分析程式只算人數、論文只有各節標題。
- 做完放回範例：第 9 步請 AI 執行 `uv run tools/new_paper.py --name 模擬論文 --restore examples/範例論文重算`。寫完的模擬論文收進 `examples/模擬論文/`，範例**複製**回 `source/`（`examples/範例論文重算/` 那份還在；不需要的話再自己刪）。
- 開始前：照第四節〈報到〉請 AI 讀 AGENTS.md 和 WORKFLOW.md；資料夾先存一版（commit），第 9 步才比得出 `source/` 有沒有完全回到原樣。實跑時另外先交代 AI「這次模擬不用紙條，直接做」。

**實跑紀錄**：2026-10-22，我們在範本的**複本**裡照下面十句話實跑一次（AI 是 Claude，在雲端跑的 Claude Code）。十步全部 `BUILD OK`，PDF 頁數依序是 1 → 1 → 1 → 4 → 4 → 8 → 12 → 13 → 13 → 8（第 9 步放回原本的範例，所以回到 8 頁）。**那次用的是 10/22 上午的範本**：之後範本改了 Fisher 檢定的算法、文獻回報要附摘要原句、AI 聲明的提醒、資料不再複製進 examples/，原本的範例也變成 9 頁。你現在照做，第 3、6、7 步的過程和頁數可能跟紀錄不一樣，新版還沒完整重跑十步。實跑時另外先給 AI 一段開場說明（扮演老師身邊的 AI 助手、這次會錄下來做成教材、照 AGENTS.md 的規矩做），並交代「這次模擬不用紙條，直接做」：研究模擬不是練習，所以用這句，不用「今天是練習」。下面「你會看到」是那次的真實結果，引號裡是 AI 的原話（摘錄）。**資料是重建的練習資料，寫出來的稿子只能練習、不能投稿。**

**第 0 步　開工、開一篇新論文**
- 跟 AI 說：「我們來做研究模擬：只給資料和文獻，請你一步一步把論文寫出來。先執行 uv run tools/new_paper.py --keep-data --refs material/模擬/refs.bib --name 範例論文重算，把範例收進 examples/、開一篇新論文；再跑一次 build，告訴我最後一行。」
- 你會看到：`BUILD OK pages=1 undefined_cites=0 undefined_refs=0 refs=13 refs_without_doi=0 bib_warnings=0`。AI 說：「PDF 編出來了、只有 1 頁（骨架而已）；書目有 13 篇，都有 DOI、沒有缺欄位……分析程式目前只算了人數：N = 140。」
- 你要看什麼：`refs=13` 代表書目換成模擬用的 13 篇了；原本的範例收在 `examples/範例論文重算/`，沒有被刪。

**第 1 步　先讀懂原料**
- 跟 AI 說：「請讀 material/模擬/研究構想.md、source/data/README.md 和 source/refs/refs.bib，告訴我：資料有幾筆、有哪些欄位、書目有幾篇、每一篇一句話講它在做什麼（只能根據摘要）。先不要改任何檔。」
- 你會看到：沒有改檔，`BUILD OK pages=1 …`。資料 140 筆（介入組 70、對照組 70）、19 個欄位、沒有缺值；書目 13 篇，每篇一句話。它說出哪兩篇沒有摘要、只能當方法出處（GEE 的方法論文、效果量的書），也先提醒：「ADQ 量表在 refs.bib 裡沒有出處。……到第 5 步寫 Methods 時，ADQ 的英文全名和出處我會標『待老師補』，不會憑記憶寫。」
- 你要看什麼：數字跟你知道的對不對得上；挑一兩篇用 DOI 打開摘要，對 AI 那句一句話。

**第 2 步　提分析計畫，等你同意**
- 跟 AI 說：「請依研究構想提出分析計畫：表 1、表 2、表 3（GEE）各放什麼、用什麼檢定、效果量怎麼算、圖 1 怎麼畫，列出會產生的數字代號和檔名。先不要改，等我同意。」
- 你會看到：沒有改檔，`BUILD OK pages=1 …`。計畫寫了每張表用什麼檢定（類別變項事先定好規則：每一格的期望人數都有 5 人以上用卡方檢定，有一格不到 5 人改用 Fisher 精確檢定，「規則先定，不看結果換檢定」）、效果量 Cohen's d（兩組差了幾個標準差）怎麼算、GEE（廣義估計方程式，分析同一個人量了好幾次的統計方法）放哪些變項、圖 1 的樣子，以及所有數字代號和檔名。AI 也提醒：「只有 2 家機構、以機構為單位分派：機構的影響跟組別完全分不開……我建議寫進限制，並請老師問統計顧問要不要另外處理。」
- 你要看什麼：**統計方法由你決定**，這是整個模擬最要緊的關卡。調整變項怎麼挑、人數少的類別怎麼併、要不要做多重比較校正，不確定的先問統計顧問；點頭了才回「同意」。

**第 3 步　做表 1～3**
- 跟 AI 說：「同意。請照計畫改 source/scripts/analyze.py，先做表 1、表 2、表 3，結果數字寫成代號，表同時輸出 .tex 和 .csv。在 main.tex 的 Results 放進三張表（先不用寫說明文字）。跑一次 build，告訴我最後一行，我會用 Excel 打開 output/tables/ 的 csv 核對。」
- 你會看到：`BUILD OK pages=4 …`。AI 另寫一段不用 analyze.py 的程式重算核對（例如 DKAS 第 12 週介入組 37.04、對照組 30.43）。它自己修掉兩個 build 不會擋的問題：SciPy（Python 的統計工具包）的 Fisher 檢定「超過 2×2 時預設用亂數模擬，每跑一次 p 值都不一樣」，改成完整列舉、每次結果一樣；表 1 第一版「太寬（超出版面 79 pt）」，縮短列名。
- 你要看什麼：用 Excel 打開 `output/tables/` 的 table1～3.csv，挑幾格跟 PDF 對（只看，按「不要儲存」）。實跑時 AI 沒有真的開 Excel，是另寫程式重算；**你自己對過，才算你核對過**。打開 PDF 看表有沒有超出版面：BUILD OK 不代表版面沒問題。

**第 4 步　畫圖 1**
- 跟 AI 說：「請畫圖 1：三個量表在三個時間點的平均和標準差，兩組各一條線。analyze.py 產生小表，source/gnuplot/ 寫一支腳本，main.tex 放進 Results。跑一次 build。」
- 你會看到：`BUILD OK pages=4 …`（圖跟表 2 排在同一頁，所以還是 4 頁）。多了三張小表 `output/figdata/fig1_*.csv` 和腳本 `source/gnuplot/fig1_means.gp`；AI 打開 PDF 看過點和誤差線沒被切掉，並提醒：「欄位號碼錯了 build 還是會 OK，只是畫錯資料，所以要打開 PDF 跟表 2 對。」
- 你要看什麼：PDF 的圖 1 挑一兩個點跟表 2 的平均對；圖說寫清楚誤差線是標準差。

**第 5 步　寫 Methods 和 Results**
- 跟 AI 說：「請依研究構想和 output/numbers.tex 起草 Methods 和 Results。數字一律用代號，表和圖都要在內文提到，Methods 的量表要引用 refs.bib 裡的出處。跑一次 build。」
- 你會看到：`BUILD OK pages=8 …`。AI 用程式把 Methods、Results 直接打出來的數字全部列出來，只剩 12 週、0–50 分這類設計上的固定值，沒有手打的結果；兩個量表的引用都附上摘要原句。要你補的地方印成**紅字方括號**，共 3 處：IRB 名稱和編號、課程內容和導師資格、ADQ 的全名和出處（「照規矩標紅字，不從範例或記憶補」）。它也列出「數字會自動更新、句子要重讀」的地方。
- 你要看什麼：紅字＝AI 不知道、也不該自己編的東西；交稿前要全部清掉，build 不會檢查紅字。挑一句 Results 跟表對。

**第 6 步　寫 Introduction 和 Discussion**
- 跟 AI 說：「請用 refs.bib 的文獻起草 Introduction 和 Discussion。每一句講到文獻的，只寫該篇摘要真的有寫的內容；回報時列出每一句根據哪一篇。結論說到多強，先在回報裡列兩三種寫法給我選，論文裡先用最保守的。跑一次 build。」
- 你會看到：`BUILD OK pages=12 …`，13 篇用了 12 篇。回報列出 16 句講到文獻的句子，每句附摘要原句；結論給 A、B、C 三種強度，論文先用最保守的 A。AI 說：「初稿有 5 句寫得比摘要多，build 抓不到，是我逐句對摘要時改的。」
- 你要看什麼：抽查兩三句，用 DOI 打開摘要，對 AI 附的原句，確認論文那句沒有說得比摘要多。`undefined_cites=0` 只代表引用的代號存在，不代表內容對。結論說到多強，由你選。

**第 7 步　標題、摘要、兩份聲明**
- 跟 AI 說：「請寫標題、結構式摘要（250 個英文單字以內）、關鍵字，補上 AI 使用聲明和資料可得性聲明：要寫清楚這是重建的練習資料、不能投稿。跑一次 build。」
- 你會看到：`BUILD OK pages=13 …`。標題寫出「reconstructed practice data」，第一頁加註腳寫明不能投稿。build 不會檢查摘要字數，AI 把 PDF 轉成純文字再數：摘要初稿 268 個英文單字，刪了三輪到 241 個。AI 使用聲明只寫真的做過的事，老師做過的檢查留一處紅字：「老師還沒做的事我不能先寫成做了。」
- 你要看什麼：AI 使用聲明逐句問自己「我真的做了嗎」；紅字那處填上你真的做過的檢查。字數請 AI 用程式量，留一點餘裕。

**第 8 步　交稿前檢查**
- 跟 AI 說：「請照 WORKFLOW.md 第 8 步的檢查清單逐條檢查，列出沒過的項目和建議怎麼改，先不要改。」
- 你會看到：沒有改檔，`BUILD OK pages=13 …`。10 條逐條查，三條沒過：「這份稿子能當練習稿看，不能投：練習資料（第 9 條）、統計顧問（第 7 條）、紅字（第 6 條和 Methods）三件事沒過。」另外列出 `bib_warnings=0` 抓不到的書目格式問題（例如量表名稱被排成小寫、兩篇缺文章編號），和三個可以帶去問統計顧問的問題。
- 你要看什麼：每一條沒過的，逐條決定怎麼處理；資料資格、倫理資訊、不實的聲明、還沒解決的方法問題，處理好之前不能投稿。`bib_warnings=0` 只代表書目欄位不缺。

**第 9 步　收起模擬論文，放回範例**
- 跟 AI 說：「模擬做完了。請執行 uv run tools/new_paper.py --name 模擬論文 --restore examples/範例論文重算，把這篇收進 examples/、把原本的範例搬回來，再跑一次 build。」
- 你會看到：`BUILD OK pages=8 undefined_cites=0 undefined_refs=0 refs=7 refs_without_doi=0 bib_warnings=0`，回到原本的範例。AI 用 git 比對過，`source/` 跟模擬開始前完全一樣；它也說：「『搬回來』其實是複製回來：examples/範例論文重算/ 還在……不需要的話，老師可以自己刪掉，我不刪檔。」
- 你要看什麼：頁數回到原本範例的頁數（現在的範本是 `pages=9`；那次實跑是 8）、`refs=7`，就是原本的範例。AI 貼的檔案清單裡出現 `\346\250\241…` 這種數字，是 git 把中文資料夾名稱印成代碼，檔案沒有壞。

**AI 自己抓到的問題**（沒有一件會讓 build 失敗，都是 AI 自己停下來說的）
- **文獻裡沒有的，它不編**：研究構想用了 ADQ 態度量表，13 篇書目裡卻沒有它的原始文獻。AI 第 1 步就提醒，第 5 步標紅字「待老師補」，沒有從範例或記憶補一個出處。
- **研究設計的限制，它先講**：兩家機構、以機構為單位分派，機構本身的差別跟組別分不開。原論文在限制段就談到兩家機構的差異；給 AI 的研究構想故意沒抄進這一點，AI 第 2 步還是自己提出來，建議寫進研究限制、問統計顧問；第 8 步清單「統計方法跟研究設計相符」那一條也沒過。
- **結果跟原論文不一樣，它說得出原因**：GEE 要用到同一個人三次分數之間的關係，練習資料裡這個關係是假設的（0.5），所以 GEE 結果不會跟原論文一樣。
- **寫得比摘要多，它逐句對才抓到**：第 6 步初稿有 5 句寫得比文獻摘要多，三種錯：替「上面引用的研究」做的總結寫錯了；把作者的結論寫成受訪者說的話；一句沒有引用、聽起來像結論的轉折句。build 完全抓不到，你抽查時也找這三種。
- **AI 使用聲明，差點替你寫了還沒做的事**：範例的聲明寫著每篇引用都對過 DOI、作者看過改過；照抄就等於替老師寫了還沒做的事。AI 拆成「AI 做了什麼」（真的做過的）和一處紅字「老師要確認的」。

**模擬之後我們改了什麼**
- **研究資料不再跟著複製進 `examples/`**：模擬時，開新論文和第 9 步都把 `source/data/` 的資料檔一起複製進 `examples/`，換成真的研究資料就可能跟著推上 GitHub。現在收進 `examples/` 時只留欄位說明，資料檔不複製。
- **Fisher 精確檢定改成完整列舉**：SciPy 碰到超過 2×2 的表，預設用亂數模擬，每次 build 的 p 值都會差一點，build 也抓不到；現在範本改成把所有可能的分法一個一個算，每次結果都一樣。
- **`--restore` 是「複製」回來，不是「搬」回來**：跑完之後 `examples/` 裡那份還在，不需要的話再自己刪。

## 六、你自己的論文：十步

每一步：**你自己做**、**跟 AI 說**（直接複製）、**你要檢查**。句子裡的「＿＿」換成你的情況。

**第 1 步　建資料夾**
- 你自己做：用範本在 GitHub 複製一份只有你看得到的資料夾（範本頁按 Use this template，公開範圍點成 **Private**；講師放的空白範本是公開的，你建出來放研究的這份一定要 Private），再下載（clone）到電腦（這一步也可以請 AI 代勞），在 Codex 或 Claude 的 Code 打開它。做法跟第二部分一樣。
- 跟 AI 說：「請先讀 AGENTS.md 和 WORKFLOW.md，再跟我報到。」
- 你要檢查：它第一行用「領隊 ·」報到，路徑結尾是你的論文資料夾。

**第 2 步　裝工具**
- 照第三節。

**第 3 步　先跑範例**
- 照第四節的練習 2。最後一行是 `BUILD OK pages=9 …` 就代表工具都裝好了。

**第 4 步　放進你的資料**
- 你自己做：先確認符合第八節的四個條件。把去識別化的資料用 Excel 另存新檔，存檔類型選「**CSV UTF-8（逗號分隔）**」，放進 `source/data/`，在 `source/data/README.md` 照範例寫每一欄是什麼。
- 跟 AI 說：「我把資料放在 source/data/（檔名＿＿），欄位說明寫在 source/data/README.md。請讀過之後，先列出你打算怎麼改 source/scripts/analyze.py：要做哪些統計、為什麼、會產生哪些數字、表和圖。先不要改，等我同意。」
- 你要檢查：統計方法是你認可的、跟你的研究設計相符（不確定就先問統計顧問）；計畫裡沒有資料裡不存在的欄位。同意後跟它說「照這個計畫改，改完跑一次 build」。

**第 5 步　接 Zotero**
- 你自己做：
  1. 把 Zotero 更新到最新版。到 Better BibTeX 官網（retorque.re/zotero-better-bibtex）下載 `.xpi` 檔（用 Firefox 下載要按右鍵另存）；在 Zotero 選「工具 → 外掛（Tools → Plugins）」→ 齒輪 →「從檔案安裝（Install Plugin From File）」，選剛下載的檔。
  2. 建這篇論文的文獻集，按右鍵「匯出文獻集（Export Collection）」→ 格式選 Better BibTeX、勾「保持更新（Keep updated）」→ 存成 `source/refs/refs.bib`（蓋掉範例那份）。之後在 Zotero 加文獻就好。
- 跟 AI 說：「我已經把 Zotero 的文獻集匯出成 source/refs/refs.bib。請告訴我裡面有幾筆、每一筆的引用代號（cite key），以及哪幾筆沒有 DOI。」
- 你要檢查：筆數跟 Zotero 文獻集一樣；缺 DOI 的回 Zotero 補。**真的沒有 DOI 的**（例如有些台灣的中文期刊），在 Zotero 給那一篇加一個標籤 `nodoi`，build 才會放行，並在結果裡列出來提醒你自己對一次。
- 其他接法（讓 AI 操作 Zotero、不裝外掛）寫在 `WORKFLOW.md` 第 2 步。

**第 6 步　起草一節**
- 跟 AI 說：「請照 WORKFLOW.md 第 5 步，用 refs.bib 裡的文獻起草 Introduction，大約三段。每一句講到文獻的，只寫該篇摘要真的有寫的內容，並在回報裡列出每句根據哪一篇；數字一律用代號。寫完跑一次 build，把最後一行給我看。」
- 你要檢查：挑兩三句，用 DOI 打開原文對一次；論點是你要的。

**第 7 步　加一張圖**
- 跟 AI 說：「請照 WORKFLOW.md 第 4 步，加一張圖：＿＿（例如兩組從前測到第 12 週的改變量，三個量表並排）。分析程式要產生它需要的資料表，main.tex 要放進去並加圖說。做完跑一次 build，告訴我最後一行。」
- 你要檢查：PDF 裡多了這張圖，數字跟表格對得上，點和誤差線沒有被切掉。

**第 8 步　交稿前檢查**
- 跟 AI 說：「請照 WORKFLOW.md 第 8 步的檢查清單逐條檢查，列出沒過的項目和建議怎麼改，先不要改。」
- 你要檢查：每一條沒過的，你決定要不要改。

**第 9 步　換期刊或出 Word**
- 你自己做：把投稿須知存成文字檔放進 `material/`。
- 跟 AI 說：「我要投的期刊是＿＿，投稿須知在 material/。請列出 main.tex 要改的地方（期刊範本、字數、引用格式、圖表規定），先列給我看。期刊只收 Word 的話，請執行 uv run build.py --docx，告訴我 Word 檔在哪裡、哪裡要人工檢查。」
- 你要檢查：Word 版的排版、表格、圖、引用格式要人工看一次。**每次產生都會蓋掉舊的 `output/main.docx`**，要在 Word 裡改，先另存到別的資料夾。PDF 是這條流程的排版基準；實際投稿交哪一種檔，照期刊規定。
- 論文或文獻有中文：跟 AI 說「論文裡有中文，請照 WORKFLOW.md 第 5 步改用 xelatex，再跑一次 build」。只要改 main.tex 第一行，中文字型已經設好。

**第 10 步　存一版、推上去**
- 你自己做：確認 `source/data/`、`material/` 裡沒有不該上傳的檔。
- 跟 AI 說：「請把今天改的檔案列給我看，特別標出 source/data/ 和 material/ 裡新放的檔。我同意之後，存一版並推上 GitHub，再告訴我去哪裡下載雲端編好的 PDF。」
- 你要檢查：GitHub 上的儲存庫是 Private；到儲存庫的 Actions 頁面，下載最新那一次的 paper-pdf。`output/` 不會推上去，雲端會自己重做一份。

## 七、出錯怎麼辦

build 失敗時，最後一行會寫 `BUILD FAILED` 和原因（缺哪個工具、哪篇文獻沒有 DOI、去看哪個檔）。把那段整個貼給 AI：

> build 失敗了，訊息如上。請照它說的去看，告訴我是什麼問題、你打算怎麼修；我同意之後再修，修好再跑一次 build，把最後一行給我看。

## 八、守住這四件事

1. **研究資料：四個條件都符合才放**（見 `source/data/README.md`）：去識別化；IRB 允許用每一家會碰到資料的 AI 工具，而且實際用的帳號、方案與設定符合核准條件（例如關掉「用我的資料改進模型」；不能只看是不是「學校／企業方案」）；資料管理計畫允許存放在 GitHub 這種境外雲端；儲存庫是 Private。**Private 不等於可以放受試者資料。** 核准文件沒有寫到生成式 AI 或境外雲端的，不要自己推定可以，先問 IRB 或學校的資料管理窗口。
2. **每篇文獻都用 DOI 回原文。** build 通過只代表引用的文獻在書目檔裡，不代表書目正確、也不代表 AI 的描述正確。
3. **結論說到多強，由你決定。** AI 起草，你拍板。數字會自動更新，解讀不會：數字變了，相關的句子要重讀。
4. **照期刊規定聲明 AI 使用。** 範本的 `main.tex` 已放了一段可以改：寫出用了哪個 AI 工具、做什麼、你怎麼把關。**聲明裡每一句都要是你真的做過的事**，例如沒有逐篇對過文獻，就不要寫「每篇都核對過」。
