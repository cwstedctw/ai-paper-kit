# 研究論文範本（ai-paper-kit）：老師的使用說明

**一句話：你不用打指令，也不用學 LaTeX。你跟 AI 說話，AI 去改檔、跑程式；你看 PDF、做決定。**

這份說明放在 GitHub 網頁上看最好讀（打開範本頁或你自己的儲存庫，往下捲就是）。用記事本打開會看到 `**`、`|`、`>` 這些符號：`**` 夾住的是粗體，`|` 隔開的是表格，`>` 開頭的是要整段複製給 AI 的句子（`>` 不用一起複製）。

這個資料夾是一個「AI 研究小隊」加上一條論文流程：

**找文獻 → 整理書目（Zotero，免費的文獻管理軟體）→ 分析資料 → 畫圖（gnuplot）→ 寫稿（LaTeX）→ 排出 PDF（也能出 Word）**

**範例是一篇已發表的研究**：居服員的失智照護訓練（2021 年刊在 *BMC Geriatrics* 期刊，公開可免費讀，CC BY 4.0 授權；DOI 是 `10.1186/s12877-021-02075-3`，書目檔裡的代號是 Su2021）。140 位居服員分兩組，在前測、第 12 週、第 24 週各量三種分數：DKAS、ADQ、SCIDS。

原始資料沒有公開，範本裡放的是**照論文表格反推出來的練習資料**：每個人的分數是假的，但兩組的平均、標準差四捨五入後跟論文一樣，所以表 1、表 2 的 p 值都跟論文相同、效果量最多差 0.01。這份資料只能練習，不能拿來下結論。

**原論文**是 2021 年發表的那篇；**範例論文**是範本裡用練習資料重算、重寫的版本（PDF 共 9 頁），把原論文的表 1、表 2、表 4 重算一次，逐一跟論文印的數字對照（原論文的表 4，在範例 PDF 裡排成表 3）。範例論文只拿來練習，不能投稿。先照下面跑一次範例、做一次練習，再換成自己的研究。

**這份說明會一直看到的詞**（看不懂時回來這裡查）：
- **build**：一個指令（`uv run build.py`），把資料算成數字、表、圖，再排成 PDF。你不用自己打，跟 AI 說「跑一次 build」就好。最後一行是 `BUILD OK` 就是成功，`BUILD FAILED` 就是停在某一步，它會說哪裡要改。
- **代號**：給一個數字取的英文名字。例如 `DKASIntTOneMean` 代表「介入組（Int）第 12 週（TOne）DKAS 的平均（Mean）」。論文裡寫代號，排版時換成數字；資料一改，數字跟著改。
- **CSV**：Excel 打得開的表格檔，一列一筆、用逗號分欄。
- **LaTeX**：學術論文常用的排版工具。你只要看它排出來的 PDF。
- **gnuplot**：畫圖的程式，照一支小腳本（`.gp` 檔）把小表畫成圖。
- **DKAS／ADQ／SCIDS**：範例研究的三個量表：失智症知識（DKAS，0–50 分）、失智症態度（ADQ，19–95 分）、失智照護能力感（SCIDS，17–68 分）。
- **p 值**：假如兩組其實沒有差別，還會看到這麼大差距的機率。越小，越不像碰巧。
- **效果量（Cohen's d）**：兩組差多少，用「差了幾個標準差」來表示。大約 0.2 算小、0.5 算中、0.8 以上算大。
- **DOI**：DOI 是每篇論文的固定編號（像身分證號碼）。在瀏覽器網址列打 `https://doi.org/`，後面接上 DOI，按 Enter，就會開到那篇論文的頁面。例如 `https://doi.org/10.1186/s12877-021-02075-3`。
- **存一版（commit）／推上去（push）**：存一版＝在自己電腦記下資料夾這一刻的樣子，之後能回到這裡；推上去＝把存好的版本放到 GitHub。
- **儲存庫**：放在 GitHub 上的資料夾。
- **Private（私人）**：GitHub 上只有你和你邀請的人看得到。**Private 不代表研究資料可以放上去**（看第八節第 1 條的四個條件）。

## 一、你要做的只有三種事

| 你做的事 | 例子 |
|---|---|
| **跟 AI 說話** | 在 AI 助手（ChatGPT 桌面版裡的 Codex，或 Claude 桌面版裡的 Code）貼這份說明裡「跟 AI 說」後面的句子 |
| **放東西、管文獻** | 把去識別化的資料放進 `source/data/`；在 Zotero 加文獻 |
| **看成品、做決定** | 打開 `output/main.pdf`；決定統計方法、文獻、結論說到多強 |

AI 會自己改檔、跑程式；哪些動作會先跳框問你、跳出來時怎麼按，看第四節〈開始前〉底下那段。你的把關靠的是**做完之後看結果**：PDF、AI 的回報、它說改了哪些檔。

## 二、資料夾怎麼分：原料放 source，成品在 output

**一句話：你和 AI 只改 `source/`（原料）；跑一次 build，程式就把成品全部重做到 `output/`；你看 `output/main.pdf`。**

### 整個資料夾長這樣

```
ai-paper-kit/                    範本資料夾＝你的整個論文專案
├─ README.md                     這份說明（你看）
├─ AGENTS.md、CLAUDE.md          給 AI 的規則（AI 開工先讀；CLAUDE.md 只有一行，指到 AGENTS.md）
├─ WORKFLOW.md                   給 AI 的論文流程說明書
├─ build.py                      一個指令跑完整條流程（AI 執行：uv run build.py）
├─ pyproject.toml、uv.lock       Python 和套件的清單（uv 照它裝，你不用動）
│
├─ source/                       ★ 原料：要改論文，就改這裡
│  ├─ data/                      研究資料（你放進來；AI 只讀、不改）
│  │  ├─ study_data.csv          一列一個人。範例是 140 位居服員的練習資料
│  │  ├─ published_values.csv    從原論文抄下來、拿來對照的數字
│  │  └─ README.md               每一欄是什麼
│  ├─ refs/refs.bib              書目（從 Zotero 匯出）
│  ├─ scripts/analyze.py         分析程式：算數字、做表、做畫圖用的小表（AI 改）
│  ├─ gnuplot/                   畫圖腳本，一張圖一支（AI 改）
│  │  ├─ fig1_outcomes.gp        圖 1：三個量表在三個時間點
│  │  └─ fig2_effects.gp         圖 2：效果量
│  ├─ tables/                    （選用）你用 Excel 做好的表，存成 CSV UTF-8
│  ├─ figdata/                   （選用）你用 Excel 做好的畫圖資料，存成 CSV UTF-8
│  └─ paper/main.tex             論文本文（AI 寫；你看的是排出來的 PDF）
│
├─ output/                       ★ 成品：每次 build 重做，不要手改，也不推上 GitHub
│  ├─ numbers.tex                內文數字，一行一個「名字＝數字」
│  ├─ tables/                    表：table1.tex（放進 PDF）＋ table1.csv（用 Excel 打開核對）
│  ├─ figdata/                   畫圖用的小表：fig1_dkas.csv …
│  ├─ figures/                   畫好的圖：fig1.tex＋fig1.pdf …
│  ├─ main.pdf                   論文 ← 你看這個
│  └─ latex-log/                 排版過程的紀錄（出錯時才看）
│
├─ material/                     你的材料：計畫書、投稿須知（你放；AI 只讀）
├─ tools/                        小工具（AI 執行）：開新論文、重建練習資料、從 Zotero 匯出書目
├─ workspace/                    AI 的工作紀錄：inbox 紙條、outbox 報告、log.md（想知道 AI 做了什麼就看這裡）
├─ roles/、team.md               AI 小隊的角色設定（工作坊網頁第二部分教過）
└─ .github/workflows/            推上 GitHub 後，雲端自動編一份 PDF
```

**記住一條規則就好：要改結果，改 `source/`（你放資料，AI 改程式和論文）；`output/` 不用顧，跟 AI 說「再跑一次 build」就會重新長出來。** `examples/` 是開新論文時才會出現的資料夾，收著舊論文給你參考。

### 一個數字、一張表、一張圖：各要三樣東西

論文裡每一個結果都是同一個公式：**① 原料（資料）＋② 做法（程式或腳本）→ ③ 成品（LaTeX 用的檔）**，論文本文再把成品放進來。

| 要做的 | ① 原料 | ② 做法 | ③ 成品 | 論文裡怎麼放 |
|---|---|---|---|---|
| 一個數字 | `source/data/study_data.csv` 的 `dkas_t1` 欄 | `analyze.py` 算介入組平均、取名字 | `output/numbers.tex` 裡的一行：`\newcommand{\DKASIntTOneMean}{37.04}`，意思是「DKASIntTOneMean＝37.04」 | `main.tex` 寫 `\DKASIntTOneMean`，排版時換成 37.04 |
| 一張表（程式算的） | `source/data/study_data.csv` | `analyze.py` 算好、排成表 | `output/tables/table2.tex`（另有 `table2.csv` 給 Excel 看） | `\input{tables/table2.tex}` |
| 一張表（你用 Excel 做的） | `source/tables/my_table.csv` | `build.py` 自動轉成 LaTeX 表格 | `output/tables/my_table.tex` | `\input{tables/my_table.tex}` |
| 一張圖（程式算的資料） | `analyze.py` 產生的 `output/figdata/fig1_dkas.csv` | `source/gnuplot/fig1_outcomes.gp` 照小表畫 | `output/figures/fig1.tex`＋`fig1.pdf` | `\input{figures/fig1.tex}` |
| 一張圖（你用 Excel 做的資料） | `source/figdata/my_data.csv` | 一支新的 `.gp` 腳本（請 AI 寫） | `output/figures/fig3.tex`＋`fig3.pdf` | `\input{figures/fig3.tex}` |

「論文裡怎麼放」那一欄是 AI 寫進 `main.tex` 的，你不用自己打；你要記得的是 ①：**資料放對地方，其他交給 AI 和 build。**

**下面兩小節寫自己的論文時才用得到，第一次讀可以先跳到第三節。**

### 想放一張自己在 Excel 做好的表

1. 在 Excel 做表：**第一列是欄名**，下面一列一筆，不要合併儲存格。
2. 「另存新檔」→ 存檔類型選「**CSV UTF-8（逗號分隔）**」，檔名用英文（例如 `my_table.csv`），存進 `source/tables/`（沒有這個資料夾就新建一個）。不要取 `table1`、`table2` 這種名字，那是程式自己用的。
3. 跟 AI 說：「我在 source/tables/ 放了 my_table.csv，請把它放進論文的 Results，表標題寫＿＿，內文提到它，跑一次 build。」
4. 你會看到：AI 回報 build 把 my_table.csv 轉成了 `output/tables/my_table.tex`，最後一行 `BUILD OK`，PDF 多了這張表。
- 表裡有中文：build 會停下來說「中文表格要用 xelatex」，跟 AI 說「照 build 說的改用 xelatex，再跑一次」就好。
- 存成別種 CSV（存檔類型沒有寫 UTF-8 的那一種）：build 會說「不是 UTF-8」，回 Excel 照第 2 步重存。
- 要改表的內容：改 Excel、重存 CSV、再跑一次 build。不要去改 `output/` 裡的檔。

### 想用 Excel 的資料畫一張圖

1. 在 Excel 做好資料：第一列是欄名（例如 `month, intervention, control`），下面一列一個點。
2. 另存成「CSV UTF-8」，檔名用英文（例如 `my_data.csv`），存進 `source/figdata/`。
3. 跟 AI 說：「我在 source/figdata/ 放了 my_data.csv，第一欄是＿＿、第二欄是＿＿。請照 WORKFLOW.md 第 4 步寫一支 gnuplot 腳本畫成＿＿圖，放進論文的 Results，跑一次 build。」
4. 你會看到：`source/gnuplot/` 多一支 `.gp`，PDF 多一張圖。打開 PDF 看：點和線沒有被切掉，數字跟你的 Excel 一樣。

（2026-10-22 實測：用 Excel 做表和畫圖資料、照上面存檔放進去，build 都 `BUILD OK`，PDF 和 Word 版都有；表裡有中文、檔案不是 UTF-8、檔名撞到的三種情況，build 都會停下來說怎麼改。）

放了 Excel 的 CSV 之後，下次報到時 AI 可能會說「source/ 有還沒存版的新檔」，然後停下來問你（2026-10-22 用 Codex 實測就是這樣）。那是你剛放的檔，回它「那是我剛放的 Excel 檔，繼續」就好。

## 三、第一次：裝工具（只要裝一次）

**TeX 是什麼？** 論文稿是用 LaTeX 寫的，電腦裡要有一套 TeX 排版軟體，才能把它排成 PDF。Windows 裝 **MiKTeX**（第一次裝比較小，缺什麼再自動補）；Mac 裝 **MacTeX**（最完整的一套 TeX Live 的 Mac 版，比較大）。裝好就好，你不用打開它，AI 會叫它做事。

| | Windows | Mac |
|---|---|---|
| TeX | **MiKTeX**（打開「缺套件時自動安裝」） | **MacTeX**（約 6.4 GB，macOS 11 以上）；硬碟不夠改 BasicTeX（約 134 MB） |
| 畫圖 | gnuplot | gnuplot（Homebrew） |
| 統計 | **uv**：跑統計程式用的工具。它會把統計要用的 Python 和套件（統計程式的零件）自動裝在範本資料夾裡的 `.venv` 資料夾，不動電腦其他地方，你不用管它 | 同左（Homebrew） |
| 轉 Word | pandoc（期刊只收 Word 時才用得到；下面那句會一起裝） | pandoc（Homebrew） |

在 AI 助手貼（Windows 版）：

> 請幫我裝寫論文要用的工具。每裝一個之前，先告訴我要裝什麼、從哪裡裝，我同意再裝；要我輸入電腦密碼時先停下來，我自己輸入。
> 1. TeX：用 winget 裝 MiKTeX（winget install -e --id MiKTeX.MiKTeX），裝好後把「缺套件時自動安裝」設成「是」（不要選每次問我），你在背景跑的時候才不會卡住。
> 2. gnuplot：用 winget 裝（winget install -e --id gnuplot.gnuplot）。裝好後打 gnuplot --version；如果找不到、或沒有印出版本就結束（winget 建的捷徑可能缺檔），請找出 gnuplot.exe 所在的 bin 資料夾，先告訴我你打算把它加進「使用者」的 PATH、會影響什麼，我同意再加；加完請我把 Codex／Claude 關掉重開，再打一次 gnuplot --version。
> 3. uv：用 winget 裝（winget install -e --id astral-sh.uv）。裝好後請我把 Codex／Claude 關掉重開，再到範本資料夾執行 uv sync（第一次會下載 Python 和套件，要幾分鐘）。
> 4. pandoc：winget install -e --id JohnMacFarlane.Pandoc。
> 全部裝完，請一一執行 pdflatex --version、gnuplot --version、uv run python --version、pandoc --version，把版本號列給我看。

Windows 裝的過程中會遇到的三件事：
- **螢幕變暗，跳出「您要允許此 App 變更您的裝置嗎？」**：這是安裝的正常步驟。看一下視窗上寫的名稱跟 MiKTeX、gnuplot、uv、pandoc 有關，再按「是」；名稱看不懂或對不上，就按「否」，截圖問。
- **AI 說要把 gnuplot 加進 PATH**：PATH 是電腦「去哪些資料夾找程式」的清單。把 gnuplot 的資料夾加進去，只是讓電腦找得到它，不會刪任何東西，可以同意。
- **AI 請你把 Codex／Claude 關掉重開**（可能一到兩次）：
  1. 把 ChatGPT（或 Claude）整個結束：按視窗右上角的 X 之後，如果螢幕右下角的小圖示區還看得到它，在圖示上按右鍵選結束（選單字樣以你的畫面為準）。
  2. 再打開它，照行前準備第 6 項，打開同一個範本資料夾。
  3. 貼這句：「我剛把 AI 助手關掉重開了。我們在裝寫論文要用的工具，請先檢查 pdflatex、gnuplot、uv、pandoc 哪幾個已經找得到，再接著裝還沒好的；uv 裝好了但範本資料夾還沒執行過 uv sync，也幫我做。規則跟剛才一樣：每裝一個先告訴我，我同意再裝。全部裝完，請一一執行 pdflatex --version、gnuplot --version、uv run python --version、pandoc --version，把版本號列給我看。」
  4. 一直做到下面的完成判準。還有一個「找不到」，就再關掉重開一次、再貼一次這句。（2026-10-22 用 Codex 實跑這句：四樣都已經找得到時，它只跑了 uv sync，再列出四個版本號，沒有另外裝東西。）

Mac 版：

> 請幫我裝寫論文要用的工具。每裝一個之前，先告訴我要裝什麼、從哪裡裝，我同意再裝；要我輸入電腦密碼時先停下來，我自己輸入。
> 1. TeX：裝 MacTeX（brew install --cask mactex，或到 tug.org/mactex 下載，約 6.4 GB）。我的硬碟空間不夠的話，先問我要不要改裝 BasicTeX。
> 2. 用 Homebrew 裝 gnuplot、pandoc 和 uv（brew install gnuplot pandoc uv）；沒有 Homebrew 的話先告訴我。如果 brew 開始從原始碼編（訊息出現 Building from source、或跑超過 10 分鐘），先停下來告訴我，改用：pandoc 到 pandoc.org 下載官方安裝檔；gnuplot 用 micromamba 從 conda-forge 裝（只裝在使用者資料夾，不動系統）。
> 3. 到範本資料夾執行 uv sync（第一次會下載 Python 和套件，要幾分鐘）。
> 全部裝完，請一一執行 pdflatex --version、gnuplot --version、uv run python --version、pandoc --version，把版本號列給我看。

AI 說「沒有 Homebrew」時：Homebrew 是 Mac 上用來裝軟體的工具。請它先說明要怎麼裝、會不會要你輸入密碼，你同意再裝。

**要你輸入電腦密碼時**（Windows、Mac 都可能）：密碼只打在系統跳出來的那個視窗，**不要打進 AI 的對話框**。不知道是哪一組密碼、或不知道要打在哪裡，先停下來，截圖問網頁版 AI，或回信問陳老師。

**完成判準**：AI 列出四個版本號，沒有「找不到」。MacTeX 很大，建議前一天晚上裝。

**Intel 晶片的 Mac 要注意**（怎麼看自己的 Mac：左上角蘋果選單 →「關於這台 Mac」，「晶片」那一行寫 Apple M 開頭的是 Apple 晶片；「處理器」那一行寫著 Intel 的是 Intel 晶片）：新版 macOS 在 Intel 晶片上，Homebrew 常沒有現成編好的 gnuplot、pandoc，會改成從原始碼編，要好幾個小時（2026-10-22 在 Intel Mac、macOS 26 實測）。上面那句已經請 AI 遇到就停下來、改用官方安裝檔和 conda-forge，那次這樣裝不到一分鐘。Apple 晶片（M1 以後）的 Mac 通常有現成編好的版本（這點還沒實測）。

## 五、研究模擬：只給資料和文獻，AI 一步一步寫完

第四節是改一篇**已經寫好**的論文。這一節反過來：研究內容只靠三樣原料：練習資料（`source/data/`）、13 篇文獻的書目（`material/模擬/refs.bib`）和一份研究構想（`material/模擬/研究構想.md`）。AI 另外會參考範本裡的規則、工具和收起來的範例程式。你一句一句說，AI 從開一篇新論文做到交稿前檢查，最後把原本的範例放回去。

**開始前**（跟第四節一樣先報到，但這次不是練習，不要貼第四節那句「今天是練習」）
- 你自己做：照第四節〈開始前〉第 3 點打開範本資料夾。
- 跟 AI 說：「請先讀 AGENTS.md 和 WORKFLOW.md，再跟我報到。接下來是研究模擬，不是練習：這次模擬不用紙條，直接做。開始前先確認 source/ 有沒有還沒存版的修改或新增檔；有的話先列給我、停下來；沒有的話幫這個資料夾存一版（commit），存好告訴我。」
- 你要看什麼：第一行「領隊 · 」後面的路徑，最後一段是 `ai-paper-kit`；它說存好了一版。存這一版，第 9 步才比得出 `source/` 有沒有完全回到原樣。（2026-10-22 用 Codex 實跑這句：資料夾本來就沒有改過，它存的是一個「空的」還原點，這是正常的；接著第 0 步 `refs=13`、第 9 步回到 `pages=9 refs=7`，`source/` 跟還原點一模一樣。）

**接下來會發生什麼**：第 0 步把現在的範例收進 `examples/範例論文重算/`（examples＝收起來的舊論文，隨時能打開參考；研究資料不會複製進去，一律留在 `source/data/`，免得多一個地方把資料推上 GitHub），`source/` 換成新論文的骨架：練習資料留著、書目換成模擬用的 13 篇、分析程式只算人數、論文只有各節標題。第 9 步把寫好的模擬論文收進 `examples/模擬論文/`，再把範例**複製**回 `source/`（`examples/範例論文重算/` 那份還在，不需要的話自己刪）。

**實跑紀錄**：2026-10-22 上午，我們在範本的**複本**裡照下面十句話完整跑過一次（AI 是 Claude，在雲端跑的 Claude Code；開始前先給了一段開場說明，並交代「這次模擬不用紙條，直接做」）。十步都成功（`BUILD OK`）。之後範本又改過幾處，你現在照做，第 3、6、7 步的過程和頁數可能跟紀錄不一樣，用每一步的「你要看什麼」核對就好。下面引號裡是 AI 的原話（摘錄）。**資料是重建的練習資料，寫出來的稿子只能練習、不能投稿。**

**第 0 步　開工、開一篇新論文**
- 跟 AI 說：「我們來做研究模擬：只給資料和文獻，請你一步一步把論文寫出來。先執行 uv run tools/new_paper.py --keep-data --refs material/模擬/refs.bib --name 範例論文重算，把範例收進 examples/、開一篇新論文；再跑一次 build，告訴我最後一行。」

**第 1 步　先讀懂原料**
- 跟 AI 說：「請讀 material/模擬/研究構想.md、source/data/README.md 和 source/refs/refs.bib，告訴我：資料有幾筆、有哪些欄位、書目有幾篇、每一篇一句話講它在做什麼（只能根據摘要）。先不要改任何檔。」

- 你要看什麼：數字跟你知道的對不對得上；挑一兩篇用 DOI 打開摘要（怎麼打開見第八節第 2 條），對 AI 那句一句話。

**第 2 步　提分析計畫，等你同意**
- 跟 AI 說：「請依研究構想提出分析計畫：表 1、表 2、表 3（GEE）各放什麼、用什麼檢定、效果量怎麼算、圖 1 怎麼畫，列出會產生的數字代號和檔名。先不要改，等我同意。」

- 你會看到：`BUILD OK pages=4 …`（圖跟表 2 排在同一頁，所以還是 4 頁）。多了三張小表 `output/figdata/fig1_*.csv` 和腳本 `source/gnuplot/fig1_means.gp`；AI 打開 PDF 看過點和誤差線沒被切掉，並提醒：「欄位號碼錯了 build 還是會 OK，只是畫錯資料，所以要打開 PDF 跟表 2 對。」

**第 5 步　寫 Methods 和 Results**
- 跟 AI 說：「請依研究構想和 output/numbers.tex 起草 Methods 和 Results。數字一律用代號，表和圖都要在內文提到，Methods 的量表要引用 refs.bib 裡的出處。跑一次 build。」
- 你會看到：`BUILD OK pages=8 …`。AI 用程式把 Methods、Results 直接打出來的數字全部列出來，只剩 12 週、0–50 分這類設計上的固定值，沒有手打的結果；兩個量表的引用都附上摘要原句。要你補的地方印成**紅字方括號**，共 3 處：IRB 名稱和編號、課程內容和導師資格、ADQ 的全名和出處（「照規矩標紅字，不從範例或記憶補」）。它也列出「數字會自動更新、句子要重讀」的地方。

- 跟 AI 說：「請寫標題、結構式摘要（250 個英文單字以內）、關鍵字，補上 AI 使用聲明和資料可得性聲明：要寫清楚這是重建的練習資料、不能投稿。跑一次 build。」

- 跟 AI 說：「請照 WORKFLOW.md 第 8 步的檢查清單逐條檢查，列出沒過的項目和建議怎麼改，先不要改。」

**第 9 步　收起模擬論文，放回範例**
- 跟 AI 說：「模擬做完了。請執行 uv run tools/new_paper.py --name 模擬論文 --restore examples/範例論文重算，把這篇收進 examples/、把原本的範例搬回來，再跑一次 build。」
- 你會看到：`BUILD OK pages=9 undefined_cites=0 undefined_refs=0 refs=7 refs_without_doi=0 bib_warnings=0`，回到原本的範例（那次實跑是 `pages=8`；範本後來多了一頁，現在照做是 9 頁）。那次 AI 用 git 比對過，`source/` 跟模擬開始前完全一樣；它也說：「『搬回來』其實是複製回來：examples/範例論文重算/ 還在……不需要的話，老師可以自己刪掉，我不刪檔。」

**AI 自己抓到的問題**（沒有一件會讓 build 失敗，都是 AI 自己停下來說的）
- **文獻裡沒有的，它不編**：研究構想用了 ADQ 態度量表，13 篇書目裡卻沒有它的原始文獻。AI 第 1 步就提醒，第 5 步標紅字「待老師補」，沒有從範例或記憶補一個出處。
- **研究設計的限制，它先講**：兩家機構、以機構為單位分派，機構本身的差別跟組別分不開。原論文在限制段就談到兩家機構的差異；給 AI 的研究構想故意沒抄進這一點，AI 第 2 步還是自己提出來，建議寫進研究限制、問統計顧問；第 8 步清單「統計方法跟研究設計相符」那一條也沒過。
- **結果跟原論文不一樣，它說得出原因**：GEE 要用到同一個人三次分數之間的關係，練習資料裡這個關係是假設的（0.5），所以 GEE 結果不會跟原論文一樣。
- **寫得比摘要多，它逐句對才抓到**：第 6 步初稿有 5 句寫得比文獻摘要多，三種錯：替「上面引用的研究」做的總結寫錯了；把作者的結論寫成受訪者說的話；一句沒有引用、聽起來像結論的轉折句。build 完全抓不到，你抽查時也找這三種。
- **AI 使用聲明，差點替你寫了還沒做的事**：範例的聲明寫著每篇引用都對過 DOI、作者看過改過；照抄就等於替老師寫了還沒做的事。AI 拆成「AI 做了什麼」（真的做過的）和一處紅字「老師要確認的」。

**模擬之後**：模擬時發現的兩個問題（研究資料會跟著複製進 `examples/`、Fisher 精確檢定每次的 p 值差一點），範本都已經修好，你不用做什麼。

## 七、出錯怎麼辦

**AI 回報 `BUILD FAILED` 時**：後面會寫原因（缺哪個工具、哪篇文獻沒有 DOI、去看哪個檔）。說「有檔案被別的程式開著」的，先關掉 PDF、Excel、Word，再請它跑一次就好。其他的，貼：

> build 失敗了，訊息如上。請照它說的去看，告訴我是什麼問題、你打算怎麼修；我同意之後再修，修好再跑一次 build，把最後一行給我看。

**看到的跟這份說明寫的不一樣時**（數字、頁數、檔名不一樣），貼：

> 你的結果跟說明書寫的不一樣：說明書寫＿＿，你給我的是＿＿。請先不要改任何檔，告訴我差在哪裡、為什麼、要不要緊。

**AI 很久沒反應，或跳出看不懂的系統視窗**（AI 的核准框照第四節〈開始前〉底下那段處理）：先別按。截圖（截圖前先關掉有姓名、密碼的視窗），貼到網頁版的 ChatGPT 或 Claude，照行前準備第 1 項的求救方法問：請它先只看、不要動，再一步一步帶你。

## 八、守住這四件事

1. **研究資料：四個條件都符合才放**（細節見 `source/data/README.md`）：
   - ① 去識別化。
   - ② IRB 允許你用每一家會碰到這份資料的 AI 工具，而且你實際用的帳號、方案與設定符合核准條件（例如關掉「用我的資料改進模型」）。不能只看是不是學校／企業方案，要看合約和 IRB 允不允許。
   - ③ 資料管理計畫允許把資料放在 GitHub 這種境外雲端。
   - ④ 你的 GitHub 儲存庫是 Private。

   **Private 不等於可以放受試者資料。** 核准文件沒有寫到生成式 AI 或境外雲端的，不要自己推定可以，先問 IRB 或學校的資料管理窗口。
2. **每篇文獻都用 DOI 回原文。** build 通過只代表引用的文獻在書目檔裡，不代表書目正確、也不代表 AI 的描述正確。DOI 是每篇論文的固定編號（像身分證號碼）。在瀏覽器網址列打 `https://doi.org/`，後面接上 DOI，按 Enter，就會開到那篇論文的頁面。例如 `https://doi.org/10.1186/s12877-021-02075-3`。
3. **結論說到多強，由你決定。** AI 起草，你拍板。數字會自動更新，解讀不會：數字變了，相關的句子要重讀。
4. **照期刊規定聲明 AI 使用。** 範本的 `main.tex` 已放了一段可以改：寫出用了哪個 AI 工具、做什麼、你怎麼把關。**聲明裡每一句都要是你真的做過的事**，例如沒有逐篇對過文獻，就不要寫「每篇都核對過」。
